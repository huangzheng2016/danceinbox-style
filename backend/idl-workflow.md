# IDL Workflow Reference

Full reference for the Thrift IDL + `hz` codegen workflow. Read this when adding endpoints, restructuring services, or writing the first version of `idl/*.thrift`.

Companion to `SKILL.md` section "IDL-First Workflow". The Iron Rule lives in `SKILL.md` — this doc is HOW.

## Files and Roles

| File | Purpose | Edited by |
|------|---------|-----------|
| `idl/base.thrift` | Shared structs (paged response, error envelope) | hand |
| `idl/api.thrift` | Public service registry. Pure `include` + `service { ... }` lines. | hand |
| `idl/papi.thrift` | Admin service registry. Same pattern. | hand |
| `idl/api/<feature>.thrift` | Per-feature methods + DTOs. | hand |
| `biz/handler/api/<feature>_service.go` | Generated stubs. ONLY function bodies are edited. | hz generates, you fill |
| `biz/handler/papi/<feature>_service.go` | Same. | hz generates, you fill |
| `biz/router/api/<feature>.go` | Route registration. NEVER edit. | hz, overwritten |
| `biz/router/api/middleware.go` | Per-route middleware stubs `_fooMw()`. | hand, hz preserves |
| `biz/router/papi/middleware.go` | Same for admin. | hand, hz preserves |
| `biz/router/register.go` | Calls `api.Register(r)` + `papi.Register(r)`. | hz, overwritten |
| `biz/model/api/<feature>/*.go` | Request/response Go structs. | hz, overwritten |

## Canonical `base.thrift`

```thrift
namespace go base

struct PageResp {
    1: required i64 total
    2: required i32 page
    3: required i32 page_size
}

struct EmptyResp {
    1: required i32 code = 0
    2: optional string msg
}
```

List endpoints take flat `page`/`page_size` fields, never `offset`/`limit` in the IDL — and there is no shared `PageReq` struct: query binding does not nest structs, so every list Req declares the two fields itself (with the usual `= 1` / `= 20` defaults). The service converts at its boundary:

```
offset = (page - 1) * page_size
limit  = page_size
```

then clamps via `mysql.ClampList(offset, limit)` and calls `FindByPage(offset, limit)` (clamp rules: `data-conventions.md` "Pagination"). The IDL-written defaults (`= 1`, `= 20`) are INERT — `BindAndValidate` never applies them, so omitted fields arrive as `0` and the clamp decides the effective page/size; normalize before echoing `page`/`page_size` in the response (details: `data-conventions.md`).

`EmptyResp` and `PageResp` exist to be USED, not just defined:
- An endpoint with no payload beyond `code`/`msg` (logout, refresh, delete) returns `base.EmptyResp` directly — it does NOT get its own `<Method>Resp` struct.
- A list response embeds `base.PageResp` for `total`/`page`/`page_size` instead of re-declaring those fields per feature.

## Canonical `api.thrift` Skeleton

```thrift
include "api/user.thrift"
include "api/example.thrift"
include "base.thrift"
namespace go api

service UserService {
    user.UserInfoResp GetUserInfo(1: user.UserInfoReq req) (api.get="/api/user/info")
    user.UserLoginResp UserLogin(1: user.UserLoginReq req) (api.post="/api/user/login")
    base.EmptyResp UserRefresh(1: user.UserRefreshReq req) (api.get="/api/user/refresh")
    base.EmptyResp UserLogout(1: user.UserLogoutReq req) (api.get="/api/user/logout")
}

service ExampleService {
    example.ExampleListResp ListExamples(1: example.ExampleListReq req) (api.get="/api/example/list")
}
```

## Canonical Per-Feature Thrift (`idl/api/user.thrift`)

```thrift
include "../base.thrift"
namespace go api.user

struct UserInfoReq {
}

struct UserInfo {
    1: required i64 id
    2: required string username
    3: required string email
    4: required string role  // "USER" | "MODERATOR" | "ADMIN"
    5: optional string avatar
}

struct UserInfoResp {
    1: required i32 code = 0
    2: optional string msg
    3: optional UserInfo user
}

struct UserLoginReq {
    1: required string identifier  // username or email
    2: required string password
}

struct UserLoginResp {
    1: required i32 code = 0
    2: optional string msg
    3: optional UserInfo user
}

// Refresh/logout take no parameters, but every IDL method still needs an
// explicit Req struct. Their responses are base.EmptyResp (declared in
// api.thrift) — no domain payload, so no per-method Resp struct here.
struct UserRefreshReq {
}

struct UserLogoutReq {
}
```

## Two Model Trees

There are two unrelated `model` directories. Mixing them up is the most common way agents end up hand-writing generated code.

| Tree | Produced by | You edit? | Contains |
|------|-------------|-----------|----------|
| `biz/model/api/**`, `biz/model/base/**` | `hz`, from thrift | NEVER | Request/response DTOs. Header `// Code generated by thriftgo (...). DO NOT EDIT.`, fields carry `thrift:"..." form:"..." json:"..." query:"..."` tags. |
| `biz/dal/mysql/model/**` | YOU, by hand | YES — this is the schema source | GORM structs with `gorm:"column:..."` tags + `TableName()`. The ONLY model directory that is hand-written. |
| `biz/dal/mysql/query/**` | `gorm/gen`, from the structs above | NEVER | Typed DAO layer (`query.User`, `.Where(...)`). Header `// Code generated by gorm.io/gen. DO NOT EDIT.` |

Services accept and return DAL models (`dal/mysql/model.User`). Handlers accept and return thrift models (`biz/model/api/user.UserInfoResp`). Convert explicitly with a helper in a hand-written file inside the DAL model package (that package is hand-maintained, so adding methods is allowed):

```go
// biz/dal/mysql/model/user_thrift.go (hand-written, lives next to user.go)
package model

import (
    apimodel "<MODULE_NAME>/biz/model/api/user"
    "<MODULE_NAME>/utils"
)

func (u *User) ToThrift() *apimodel.UserInfo {
    return &apimodel.UserInfo{
        ID:       u.ID,
        Username: u.Username,
        Email:    u.Email,             // required in the IDL — never omit
        Role:     u.Role,
        Avatar:   utils.Ptr(u.Avatar), // optional in the IDL → *string
    }
}
```

Every `required` field of the thrift struct must be populated here — `email` is required in `UserInfo`, so dropping it silently ships an empty email to the client. Optional thrift fields generate pointer fields in Go (`Avatar *string`); map them with `utils.Ptr` when the DAL column is a plain value.

Never dodge this hop by defining a parallel `type userDTO struct` inside a handler or service file.

## Naming Rules

- Service name: `<Domain>Service`, PascalCase, ends with `Service`. Maps to `biz/handler/api/<domain>_service.go`.
- Method name: PascalCase verb-noun. `GetUserInfo`, `ListChallenges`, `CompetitionSignUp`. NOT `getUserInfo` or `get_user_info`.
- Request/response: `<Method>Req` / `<Method>Resp`. Both required even if empty.
- URL path: lowercase snake_case. `/api/user/info`, `/api/challenge/list`, `/api/challenge/list_solved`.
- Inside a Resp, field 1 is `i32 code`, field 2 is `optional string msg`. Domain payload starts at field 3.
- `code = 0` means success. Non-zero codes live in `biz/consts/errcode.go`.

## hz Commands

Install first, before anything else (pin policy and upgrade rules: SKILL.md "Codegen Toolchain"):

```bash
go install github.com/cloudwego/hertz/cmd/hz@v0.9.7
```

First generation (run ONCE at project birth):
```bash
hz new -idl idl/api.thrift -mod <MODULE_NAME> -handler_dir biz/handler -model_dir biz/model
hz update -idl idl/papi.thrift -handler_dir biz/handler -model_dir biz/model
```

`hz new` drops a `.hz` metadata file at the repo root (records hz version + handler/model dirs). COMMIT it and never delete it — `hz update` reads it and will silently mis-target without it.

Every subsequent change goes through `script/hz_update.sh`:
```bash
#!/bin/bash
set -euo pipefail
cd "$(dirname "$0")/.."

hz update -idl idl/api.thrift -handler_dir biz/handler/ -model_dir biz/model
hz update -idl idl/papi.thrift -handler_dir biz/handler/ -model_dir biz/model
```

Every thrift file under `idl/` MUST be reachable from one of these two invocations. An IDL file that `hz_update.sh` skips ("anchor only", "for docs") is a decoy and is forbidden — its routes will be hand-registered somewhere, which is exactly the drift this workflow exists to prevent.

`hz update` is idempotent. Safe to run repeatedly. It will:
- Append new method stubs to existing `biz/handler/<area>/<service>.go`.
- Regenerate `biz/router/<area>/*.go` files entirely.
- Preserve hand-edited bodies inside existing handler functions.
- Preserve `biz/router/<area>/middleware.go`.

## Per-Route Middleware Stubs

After `hz update`, `biz/router/api/middleware.go` contains stubs like:
```go
func _userServiceMw() []app.HandlerFunc {
    return nil
}

func _getUserInfoMw() []app.HandlerFunc {
    return nil
}
```

These run in order: service-level mw, then per-method mw. **For any method whose handler reads the authenticated user (`mw.GetJwtId`, or a role check), the method-level `_xxxMw()` MUST return at least `mw.JwtAuthenticationMw()`**. In the default scaffold, role gating goes through `mw.RequireRoleMw(...)` / `mw.ModeratorOrAdminMw()` from `biz/mw/role.go`; `mw.CheckRoleAny` exists only after the Casbin upgrade (`biz/mw/casbin.go`) — do not reference it before then:

```go
func _getUserInfoMw() []app.HandlerFunc {
    return []app.HandlerFunc{mw.JwtAuthenticationMw()}
}
```

Without this, an expired access token with a valid refresh leaves the request in `JWT_STATUS_REFRESH`. Root `JwtParseMw` ran (set the status) but `JwtAuthenticationMw` did NOT (it would have responded 403 with `X-Token-Refresh-Needed: true`). Handler runs with `GetJwtId() == 0` and returns 200 + JSON error. The axios refresh path never fires. The user appears logged out.

For `/papi/*` you do not need to repeat `JwtAuthenticationMw + ModeratorOrAdminMw` per route — `papi.rootMw()` already chains them.

## Handler Body Pattern

```go
// biz/handler/api/user_service.go (generated stub filled in)

func GetUserInfo(ctx context.Context, c *app.RequestContext) {
    var req user.UserInfoReq
    if err := c.BindAndValidate(&req); err != nil {
        c.JSON(http.StatusBadRequest, user.UserInfoResp{
            Code: consts.ErrInvalid,
            Msg:  utils.Ptr(err.Error()),
        })
        return
    }

    uid := mw.GetJwtId(ctx, c)
    u, err := container.Default.UserService.GetByID(ctx, uid)
    if err != nil {
        c.JSON(http.StatusInternalServerError, user.UserInfoResp{
            Code: consts.ErrInternal,
            Msg:  utils.Ptr(i18n.MustGetMessage(ctx, "Error.Internal")),
        })
        return
    }

    c.JSON(http.StatusOK, user.UserInfoResp{
        Code: 0,
        User: u.ToThrift(),
    })
}
```

Rules:
- Always `BindAndValidate`. Never read query params or body manually.
- Always go through `container.Default.<Service>`. Never instantiate services in the handler.
- Always set `code` field. Use `consts.Err*` constants.
- HTTP status and body `code` tell the same story: 400/`ErrInvalid`, 401/`ErrUnauthorized`, 403/`ErrForbidden`, 409/`ErrConflict`, 500/`ErrInternal` — a mismatch desyncs the frontend interceptor (keys off HTTP status) from API consumers (read the code). 401 = unauthenticated, 403 = authenticated but not allowed; not interchangeable. One deliberate exception: `JwtAuthenticationMw` answers expired-access + valid-refresh with 403 + `X-Token-Refresh-Needed: true` as the refresh protocol signal (see `auth-jwt-casbin.md`).
- Error message goes through i18n (`i18n.MustGetMessage(ctx, "Error.Key")`). Do not hard-code Chinese or English.
- Import-block edits in the generated handler file are allowed — hz preserves them, with one limit: hz force-restores the import of the IDL model package (`biz/model/api/<feature>`) on regeneration, because the generated stub references it. If your body stops using the request type (e.g. you omit `BindAndValidate` on a no-param endpoint), that import goes unused and the build fails with `imported and not used`. Keep the `var req x.FooReq` + `BindAndValidate` boilerplate even for empty requests rather than fighting the import. The signature, the `// @router` comment, and the number of functions in the file are not editable.

## Worked Example: Adding `GET /api/example/list`

The full loop, in order. Each step's output is the next step's input — do not reorder.

1. **Schema**: hand-write `biz/dal/mysql/model/example.go` (GORM struct + `TableName()`). Add `&model.Example{}` to `model.MigratedModels()` once, then run `go run ./cmd/generate`. Generation and boot migration consume the same registry.
2. **Service**: write the failing test `biz/service/example/service_test.go` first, then implement `service.go` against `mysql.GetDBQuery().Example`.
3. **IDL**: add req/resp structs to `idl/api/example.thrift`:

```thrift
include "../base.thrift"
namespace go api.example

struct Example {
    1: required i64 id
    2: required string name
}

struct ExampleListReq {
    1: optional i32 page = 1
    2: optional i32 page_size = 20
}

struct ExampleListResp {
    1: required i32 code = 0
    2: optional string msg
    3: optional base.PageResp page
    4: optional list<Example> data
}
```

(The flat `page`/`page_size` and the embedded `base.PageResp` follow the paging rules in "Canonical `base.thrift`" above.)

and register the method inside the existing `service ExampleService` block in `idl/api.thrift`:

```thrift
example.ExampleListResp ListExamples(1: example.ExampleListReq req) (api.get="/api/example/list")
```

4. **Run** `./script/hz_update.sh`. Read what hz prints — the touched files must be confined to `biz/handler/api/example_service.go` (stub appended), `biz/router/api/`, `biz/model/api/example/`.
5. **Fill the stub hz just wrote.** Learn to recognize it — it has the `// @router` annotation and `BindAndValidate` boilerplate:

```go
// ListExamples .
// @router /api/example/list [GET]
func ListExamples(ctx context.Context, c *app.RequestContext) {
	var err error
	var req example.ExampleListReq
	err = c.BindAndValidate(&req)
	...
}
```

Fill the body per "Handler Body Pattern". Never change the signature, never move the function to another file, never copy it into a new file.
6. **Middleware**: in `biz/router/api/middleware.go`, make `_listExamplesMw()` return `[]app.HandlerFunc{mw.JwtAuthenticationMw()}` if the endpoint requires a logged-in user.
7. **Audit + verify**: `git status` (see "Generated-File Fingerprints" below), `go build ./...`, run the failing service test to green, manual smoke via curl. Commit.

## Generated-File Fingerprints (self-audit)

| Surface | Fingerprint |
|---------|-------------|
| `biz/router/**/*.go` | `// Code generated by hertz generator. DO NOT EDIT.` |
| `biz/handler/**/*.go` stubs | `// Code generated by hertz generator.` header + `// @router /api/foo [GET]` above every handler func |
| `biz/model/**/*.go` | `// Code generated by thriftgo (...). DO NOT EDIT.` + `thrift:"..."` field tags |
| `biz/dal/mysql/query/**` | `// Code generated by gorm.io/gen. DO NOT EDIT.` |
| `biz/dal/mysql/model/**` | NO generated header — hand-authored on purpose |

After running `./script/hz_update.sh` or `go run ./cmd/generate`, run `git status`: changes must be confined to `biz/handler/`, `biz/router/`, `biz/model/`, `biz/dal/mysql/query/`, plus the hand files you intended to edit (IDL, `middleware.go`, model structs, `model/registry.go`). Anything else changed: revert it and find out why before proceeding.

Commit generated output. CI starts from a clean checkout, reruns `./script/hz_update.sh`, `go run ./cmd/generate`, and `go generate ./container`, then requires no drift:

```bash
git diff --exit-code -- biz/handler biz/router biz/model biz/dal/mysql/query container
```

A generator version bump is deliberate and reviewed separately. Do not hand-edit generated files to make this check pass.

## Optional TypeScript Contracts

When the frontend needs generated types or runtime response validation, add a scoped generator from the same Thrift IDL as a separate feature. Generate TypeScript types first; add Zod schemas only when the client actually validates responses. The API client must consume the generated output, the output is committed, and CI reruns the generator with the same drift check.

Do not copy a large regex-based Thrift parser or business-field override table into the scaffold. Define the supported IDL subset and test required/optional/default fields, nested types, duplicate names, unknown references, and int64 mapping before enabling the generator. OpenAPI is optional too, justified by external API consumers or documentation needs rather than added by default.

## Manual Routes (the exceptions)

These bypass IDL and live in `router.go`'s `customizedRegister(r)`:

| Endpoint | Why exempt |
|----------|-----------|
| `/ping`, `/livez`, `/healthz` | Trivial health endpoints (`/livez` liveness, `/healthz` readiness with dependency probes; `/ping` is a legacy alias). Defined in `biz/handler/{ping,health}.go`, registered by hand. |
| Static assets (`/assets/*path`, `/admin/assets/*path`, `/favicon.ico`) | Served from `frontend_embed.go` via `serveStaticFile`. The admin bundle builds with base `/admin/`, so `admin.html` references `/admin/assets/*` — without that second route the admin SPA white-screens in embed mode. |
| SPA fallback (`/*` and `/admin/*`) | `NoRoute` handler serves `index.html`, and `admin/admin.html` for paths under `/admin`. |
| WebSocket upgrades | Hijacks the connection. Set `h.NoHijackConnPool = true`. |

Server-Sent Events still use the IDL/hz route, generated request DTO, middleware, and policy registry. The generated handler writes the `text/event-stream` response directly; exclude that route from gzip and ETag. Streaming the response body is not a reason to hand-register the route.

**ANY OTHER `/api/*` or `/papi/*` ROUTE MUST GO THROUGH IDL.** No exceptions for "it's small" or "it's temporary". File uploads, webhooks, admin utilities, debug endpoints, and SSE all retain the IDL contract. Only the WebSocket upgrade and the root/static exceptions above bypass it; they do NOT get a thrift file that `hz_update.sh` skips or a `manual.go` registration helper.

## When the Generated Code Looks Wrong

- `hz update` overwrote your handler body? It does not. If a body went missing, you either (a) deleted it yourself, (b) the function signature in the IDL changed and `hz` re-created the stub. Check git.
- New route is not registered? Re-run `./script/hz_update.sh` and check `git status`: if nothing under `biz/router/**` changed, your IDL annotation is wrong (missing `(api.get=...)` / `(api.post=...)`) or you only ran one of the two hz invocations. `biz/router/register.go` must list both `api.Register(r)` and `papi.Register(r)` — if it does not, hz's run was interrupted; re-run it. NEVER hand-edit `register.go` to "fix" registration.
- `import "<MODULE_NAME>/biz/model/api/foo"` does not exist? You ran `hz update` against only one of api/papi. Re-run for both.
- Middleware stub `_fooMw()` keeps reverting to `return nil`? You are on an old `hz`. The pinned toolchain (`hz` v0.9.7, see "Codegen Toolchain" in SKILL.md) preserves edited stubs. Upgrade.
